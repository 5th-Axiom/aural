# 中文面试、手机号、岗位与简历追问

本期保留原有文字/实时语音面试、逐题追问和报告流程。默认界面为中文，原有中英文切换仍可使用。

## 本地体验

本地 Supabase 已应用 `006_phone_roles_resume.sql`，`.env.local` 已启用模拟手机号登录。启动网页：`npm run dev -- --port 3001`；语音中继：`npm run dev:voice`。

1. 打开 `http://localhost:3001/login`。手机号可以任意填写，验证码固定为 `123456`，不会发送真实短信。
2. 创建面试时填写岗位；也可选择模板，继承模板岗位或指定新岗位。已有面试可在「设置」中修改岗位。
3. 在面试编辑页的「内容 → 简历定向追问」选择/新建候选人，填写该候选人将用于登录的手机号，上传 PDF、TXT 或 MD 简历，点击「解析并插入追问」。
4. 生成成功后显示 2–3 道专属题及对应简历依据。候选人用相同手机号登录并打开公开面试链接或个人邀请链接后，获得基础题和自己的简历题。
5. 后台「会话」可查看手机号和岗位，并按岗位筛选或检索；会话详情与导出保留这些字段。

同一手机号对应同一账号，不同手机号拥有独立账号。验收用本地管理员标识为 `feature-test-001`，验证码同上，其中有独立的「中文面试功能验收」数据。原邮箱账号和历史记录没有删除。

## 数据与模型职责

- 简历提问规则集中在 `src/lib/prompts/resume-questions.ts`。模型根据简历、岗位、面试目标和基础题自动提问，不允许简历内的指令覆盖系统要求。
- 工程层校验文件类型/大小、文本长度、题目数量、重复题和原文引用。请求或校验失败最多尝试 3 次，携带上次校验反馈。
- PDF 需包含可提取文本；扫描图片简历须先 OCR。单文件最多 5 MB，解析文本为 30–40000 字符。
- 专属题通过 `questions.candidateId` 绑定候选人。公开访问、候选人会话、文字模型、语音初始化和报告都按候选人过滤；复制面试及跨面试导题仅使用基础题。
- 候选人开始后专属题锁定，防止改写正在进行或历史面试的题目。
- `interviews.roleTitle` 是岗位；`sessions.roleTitle` 保存发起时的快照，随后修改岗位不会改写历史会话。
- 手机号从服务端验证的账号 `app_metadata` 写入候选人和会话，客户端不能在创建会话时冒填另一个手机号。

## 部署前置步骤

2026-09-09 已发布至 https://47.108.226.96 。管理员手机号 `13800138000`，候选人样例 https://47.108.226.96/i/7qwc1kqn7e 使用手机号 `13800138001`，验证码均为 `123456`；入口密码沿用原值。部署步骤：

1. 在目标 Supabase 数据库事务执行 `supabase/migrations/006_phone_roles_resume.sql`。
2. 设置 `MOCK_PHONE_AUTH_ENABLED=true` 和至少 32 字符的随机 `MOCK_PHONE_AUTH_SECRET`。密钥需保持稳定，不可使用 `NEXT_PUBLIC_*` 暴露给浏览器。
3. 同步 `deploy/test/ip-nginx.conf`，移除旧的 `/login` 跳转。测试入口密码通过后将转入手机号登录，不再自动进入共享账号。
4. 执行 `npm run deploy:test`。该命令在本机构建镜像，应用发布本身不自动迁移数据库。

模拟验证码适用于本期测试。正式短信服务接入时应替换模拟验证与账号绑定方式。
